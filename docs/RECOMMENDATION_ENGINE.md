# 추천 엔진 설계

Phase 2에서 순수 TypeScript 함수로 구현한다. 현재 추천 기능은 없다.

## 계약
`recommend(games, validatedPreferences)`는 최대 5개의 고유 게임, 근거 기반 이유, 완화 내역, 제외 데이터 진단을 반환한다. 입력을 변경하지 않고 동일 입력이면 동일 결과를 낸다. DB 조회·UI·네트워크·현재 시각·난수를 사용하지 않는다. 최신성 판정이 필요하면 기준 날짜를 입력으로 받는다.

## 필수 필터
1. 필수 데이터가 누락되거나 범위가 잘못된 게임을 제외하고 내부 진단을 남긴다. 미확인 값을 0으로 채우지 않는다.
2. 정확한 모임 인원이 minPlayers~maxPlayers 안에 있어야 한다. 이 조건은 절대 완화하지 않는다.
3. 검증된 사실이 있는 게임을 사용한다. 국내 판매 확인 게임을 우선하고 국내 플레이 근거만 있는 게임은 구분한다. PENDING/REJECTED는 추천하지 않는다.
4. 시간은 분 단위 폐구간으로 정의한다: [1,15], [15,30], [30,60], [60,120], [120,∞]. 사용자가 표현한 경계가 겹치므로 15·30·60·120분은 양쪽 선택에 포함된다. 원자료의 게임 시간 범위가 선택 구간에 완전히 포함되면 엄격 일치다. 120분 이상은 최소 시간이 120 이상이어야 엄격 일치다.

## 순위와 다양성
국내 판매 확인을 우선하는 tier 내에서 추천 인원 포함, 분위기 일치, 자체 난이도 일치, 한국어 사용 편의 순으로 근거를 비교한다. 난이도 상관없음은 난이도 비교를 건너뛴다. 한국어 의존도가 높더라도 한국어판이 확인되면 사용 편의를 반영한다. 미확인은 불리하게 취급하고 이유를 명시한다.

후보 간 장르·주요 메커니즘이 지나치게 같으면 동일 tier·동일 선호 비교 그룹에서 다른 장르를 먼저 택한다. 정확히 일치하는 게임을 단지 다양성 때문에 불일치 게임 뒤로 밀지 않는다. 완전 동률은 slug로 안정 정렬한다. 내부 비교값을 사용자 적합도 백분율로 표시하지 않는다.

## 부족할 때
엄격 후보가 5개 미만이면 시간 범위가 겹치는 후보를 후순위 추가한다. 예: 30~60분 요청에 45~90분 게임은 “최대 90분이 걸릴 수 있어요”로 안내한다. 그다음 인접 시간 구간 후보만 추가하며 어떤 구간을 확장했는지 반환한다. 무제한 확장은 하지 않는다. 분위기·난이도는 원래 선호 조건이므로 불일치를 사실대로 설명한다. 검증·인원 필터는 유지하며 남은 후보가 없으면 0~4개만 반환한다. slug와 id로 중복을 막는다.

## 이유
“4명이 추천 인원에 포함돼요”, “협력 분위기에 맞아요”, “선택 시간보다 길어질 수 있어요”처럼 실제 필드·출처에서 도출한다. 근거 없는 인기·최고·정확도 표현은 금지한다.

## 예정 테스트
2인·4인·정확한 7/8/10인, 불가능 인원, 빈 목록, 시간 경계와 장시간 무한 상한, 난이도 상관없음과 차이, 분위기 일치·불일치, 완화 순서·이유, 중복 ID·slug, 누락·잘못된 범위, 입력 불변성·결정성을 검증한다.
