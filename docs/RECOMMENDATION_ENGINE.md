# 추천 엔진 — Phase 2 구현

## 범위와 계약
`src/domain/recommendation/recommend.ts`의 `recommend(games, preferences)`는 UI·React·Next·DB·네트워크·현재 시각·난수에 의존하지 않는 순수 함수다. 입력을 변경하지 않고 최대 5개의 고유 게임, 한국어 추천 이유, 시간 완화 내역, 내부 제외 진단을 반환한다. 외부 가중 점수나 적합도 백분율은 없다. 웹 화면·API 연결은 Phase 3이며 현재 준비 화면을 유지한다.

`games`는 읽기 전용 unknown 배열이다. 기존 `boardGameRecordSchema`의 출처 검증을 재사용하며 repository가 추가하는 UUID id·ISO createdAt/updatedAt도 허용한다. 게임별 구조 오류는 해당 항목만 제외한다. 출력에 원본 객체 참조를 공유하지 않는다. 같은 입력의 반복 실행은 같은 결과를 내며, 중복이 없는 정상 후보는 입력 순서를 바꾸어도 같은 순위를 낸다.

조건은 `recommendationPreferencesSchema`로 실행 시 재검증한다. 잘못된 조건은 Zod 오류를 발생시키므로 호출 경계에서 한국어 오류 화면으로 처리해야 한다. 손상된 게임 자료는 사용자 입력 오류와 구분해 diagnostics로 반환한다.

## 사용자 입력
`recommendationInputSchema`는 폼/API 경계용 계약이다. 선택값은 2·3·4·5·6·7-plus이며 7-plus에는 7 이상의 정확한 정수 exactPlayers가 필수다. 작은 인원 선택과 exactPlayers를 함께 보내면 모호한 입력으로 거부한다. exactPlayers는 숫자 또는 숫자만 있는 문자열을 허용하고, 빈 문자열·소수·지수 표기·비정상 값은 거부한다. 정규화 결과는 정확한 playerCount다. 8명을 7명으로 치환하지 않는다. 임의의 모임 상한은 추가하지 않고 안전한 정수 범위를 사용한다.

```ts
import { recommendationInputSchema } from "@/domain/recommendation/preferences";
import { recommend } from "@/domain/recommendation/recommend";

const preferences = recommendationInputSchema.parse({
  players: "7-plus",
  exactPlayers: 8,
  playTime: "BETWEEN_30_60",
  mood: "COOPERATIVE",
  difficulty: "BEGINNER",
});
// verifiedRecords는 향후 서버 조회 결과로 전달한다. 여기서 DB를 호출하지 않는다.
const result = recommend(verifiedRecords, preferences);
```

시간 선택은 UP_TO_15 / BETWEEN_15_30 / BETWEEN_30_60 / BETWEEN_60_120 / AT_LEAST_120, 분위기는 PARTY / STRATEGY / DEDUCTION / COOPERATIVE / RELAXED, 난이도는 BEGINNER / EASY / INTERMEDIATE / ADVANCED / ANY다. 한국어 레이블은 preferences 모듈에서 제공한다. 실제 URL 쿼리 파싱·폼 구현은 Phase 3 범위다.

## 필수 필터와 누락
1. 기존 데이터 계약으로 출처·필드 값·범위를 검증한다. 필수 인원·시간·출처가 누락되면 제외하며 값을 추정하지 않는다.
2. VERIFIED 사실만 사용한다. PENDING / STALE / REJECTED는 제외한다. 자동 신선도 기준을 발명하지 않고 명시된 상태를 따른다.
3. 선택한 정확한 인원이 가능 범위 안에 있어야 한다. 이 조건은 완화하지 않는다.
4. 국내 상품 확인 상태가 LISTED / IN_STOCK / OUT_OF_STOCK 중 하나이거나 국내 플레이 근거가 CONFIRMED여야 한다. 한국어판 존재나 해외 판매만으로 국내 근거를 추정하지 않는다.
5. 아래 시간 정책 안의 후보만 유지한다.

자체 편집은 VERIFIED일 때만 사용한다. PENDING / STALE / REJECTED 편집 및 편집 자체가 없는 게임은 검증된 사실만 사용하며, 추천 인원·분위기·난이도·언어 의존도의 미확인을 알린다. 평균 시간이 null이면 범위 중간값을 계산하지 않는다. 자체 소개도 미검토이면 결과에 포함하지 않는다.

## 시간 범위와 단계
모든 구간은 양끝을 포함한다: [1,15], [15,30], [30,60], [60,120], [120,∞]. 15·30·60·120분은 양쪽 구간에 속할 수 있다. ∞는 내부 비교에만 사용하며 API 결과에는 직렬화하지 않는다.

- STRICT: 게임의 전체 표기 시간 범위가 선택 구간에 들어간다. 120분 이상 선택 시 게임 최소 시간이 120 이상이어야 한다.
- OVERLAPPING_TIME: 선택 구간에 일부만 겹친다. 단, 게임 전체 범위는 선택 구간과 바로 이웃한 구간을 합친 범위 안에 있어야 한다.
- ADJACENT_TIME: 엄격 일치나 겹침 없이 바로 이웃한 한 구간에 게임 전체 범위가 들어간다.
- 그 밖은 제외한다. 두 구간 이상 떨어진 후보를 추가하지 않는다.

이는 Phase 0의 “겹치는 범위 → 인접 범위” 설계를 구체화한 것이다. 조금 겹친다는 이유로 지나치게 넓은 시간을 허용하지 않도록 겹침 단계에도 인접 구간 경계를 적용했다. 예: 30~60분 요청에 45~90분은 겹침, 90~100분은 인접, 1~600분이나 180분은 제외한다. 120분 이상 구간은 정의상 상한이 없으며 그 구간이 선택 또는 이웃 구간일 때도 이 정의를 유지한다. 예외적인 임의 상한을 만들지 않고 실제 표기 시간과 길어질 가능성을 명시한다.

엄격 후보가 5개 이상이면 완화 게임은 반환하지 않는다. 부족할 때만 겹침 후보를, 그래도 부족할 때만 인접 후보를 순서대로 보충한다. 시간 조건을 추가 완화해 5개를 채우지 않는다. 실제 후보가 0~4개라면 그 수량만 반환한다.

## 결정적 순위
아래 순서로 사전식 비교한다. 뒤 조건은 앞 조건이 같을 때만 적용한다.

1. 시간 단계: 엄격 → 겹침 → 인접.
2. 국내 확인 상태: 재고 확인 → 상품 노출(재고 미확인) → 품절 확인 → 판매 미확인·국내 플레이 근거만 확인.
3. 추천 인원: 선택 인원 포함 → 다른 추천 인원만 확인 → 미확인.
4. 분위기: 태그 일치 → 다른 태그만 확인 → 미확인.
5. 난이도: 일치 → 인접 단계 → 더 큰 단계 차이 → 미확인. 단계 순서는 입문자·초급·중급·상급이다. ANY이면 이 비교를 생략한다.
6. 한국어 사용 편의: 언어 의존도 없음 → 낮음 또는 한국어판이 확인된 중간/높음 → 한국어판 미확인의 중간 → 한국어판 미확인의 높음 → 의존도 미확인.
7. 앞선 비교가 모두 같은 그룹 안에서만 장르·메커니즘 다양성을 고려한다.
8. 완전 동률은 slug의 코드 순으로 정렬한다. 환경별 locale 순서에 의존하지 않는다.

분위기와 난이도는 선호 조건이므로 불일치 게임을 무조건 제외하지 않는다. 불일치는 CAUTION 이유로 알린다. 알려진 불일치와 미확인의 차이를 보존하며, 미확인 정보에 유리한 추정값을 부여하지 않는다. 내부 비교는 필드의 상태·정수 단계 차이만 사용하며 사용자 적합도 수치로 출력하지 않는다.

다양성은 VERIFIED 편집의 categories[0]·mechanics[0]을 주요 장르·메커니즘으로 사용한다. 이미 선택된 게임들과 주요 장르가 덜 겹치는 후보를 우선하고, 같으면 주요 메커니즘을 비교한다. 데이터 편집자는 주요 항목을 배열 첫 값으로 관리해야 한다. 누락된 태그를 새 장르로 간주하지 않는다. 다양성 때문에 앞선 시간·유통·선호 조건의 우선순위를 뒤집지 않는다.

## 결과·추천 이유
각 recommendation은 카드용 game DTO, reasons, nullable relaxation으로 구성된다. DTO에는 한국어 이름, 가능·추천 인원, 시간 범위·실제 평균(null 가능), 난이도·장르·메커니즘·언어 상태, 확인일과 detailPath가 있다. 권리 확인 이미지가 없으므로 이미지를 생성하거나 외부 URL을 넣지 않는다. detailPath는 향후 상세 페이지용 경로이며 Phase 4 전에는 UI에 연결하지 않는다.

reasons는 PLAYERS / BEST_PLAYERS / TIME / MOOD / DIFFICULTY / LANGUAGE / DOMESTIC_AVAILABILITY 코드와 MATCH / INFO / CAUTION, 한국어 메시지를 갖는다. 가능 인원과 추천 인원을 구별하고, 자체 태그는 자체 검토라는 표현을 사용한다. 품절·재고 미확인·언어 부담도 함께 설명한다. 국내 재고 확인은 확인 시점의 사실이며 현재 재고 보장을 하지 않는다. 국내 인기·최고·정확도 주장은 생성하지 않는다.

시간 완화는 게임마다 요청 구간·실제 범위·짧아지거나 길어질 수 있는 방향을 설명한다. 최상위 relaxations는 완화 코드별 적용 게임 slug를 묶으며 notices는 결과 부족과 시간 완화를 알린다. 완화되지 않은 조건을 완화했다고 표시하지 않는다.

## 중복과 진단
첫 번째 유효·적격 레코드의 slug와 존재하는 id를 유지하고, 이후 같은 slug 또는 id는 DUPLICATE_GAME으로 제외한다. 모순되는 판본 정보를 합치지 않는다. 중복 레코드의 우선권은 입력 순서를 따르므로 repository의 유일성 제약을 함께 유지해야 한다. 입력이 잘못되거나 필수 필터에서 제외된 레코드는 이후 정상 후보의 정체성을 선점하지 않는다.

진단 코드는 INVALID_GAME, UNVERIFIED_GAME, DOMESTIC_EVIDENCE_MISSING, PLAYER_COUNT_MISMATCH, TIME_OUT_OF_RANGE, DUPLICATE_GAME이다. inputIndex·검증된 slug 또는 잘못된 필드 경로만 기록하고 원시 오류 값·출처 객체를 복제하지 않는다. 최종 5개에 선택되지 않은 정상 후보는 오류로 취급하지 않는다.

## 검증과 공개 경계
2·4·7·8·10인, 결과 없음·최대 5개, 모든 시간 경계·무한 상한·완화 제한, 분위기·난이도·ANY·한국어 의존도, 중복·누락·미검토 편집, 다양성·동률, JSON 직렬화·입력 불변성을 테스트했다. 테스트 가상 게임은 `__tests__/fixtures.ts` 내부에만 있으며 운영 데이터나 seed에 추가하지 않는다. 현재 실데이터는 Phase 1의 개발용 샘플 1개뿐이고 공개 승인·이용 범위 검토는 여전히 남아 있다. 엔진의 추천 가능 판정은 공개 승인이나 재이용 허가를 대신하지 않는다.
